# P3 工作台与运行状态 Implementation Plan

> **For agentic workers:** 使用 superpowers:subagent-driven-development 或 superpowers:executing-plans，按步骤逐项验证。

**Goal:** 交付仅站长可见的工作台管理界面，并诚实显示排期、备份、磁盘、评论配置和服务人工状态。

**Architecture:** 所有写操作经过 owner、CSRF/source 和审计；工作台状态区分未配置、无记录、进行中、成功、失败、陈旧、读取失败；不探测外部服务、不显示虚构计数。

**Spec:** 正式规格主体第 2/9/10 节、功能分册第 4 节、v2 管理画板和控件细稿、视觉分册第 3/4 节。

## Steps

- [ ] 1. 写工作台授权和数据测试：20 条列表、状态组合筛选、归档、草稿/排期异常优先、系列最多一项、标签重命名、服务人工状态时间、Giscus 配置无待审核数。
- [ ] 2. 实现概览、内容、媒体、排期、评论设置、服务、站点设置、账号安全；排序使用独立上移/下移按钮，首项/末项禁用。
- [ ] 3. 实现 240px 桌面侧栏、窄屏抽屉、独立移动工作台 header、焦点进入/返回、200% 文本和 reduced-motion。
- [ ] 4. 消费 P0 定义的 `OperationalStatus` 契约；P3 只展示状态，不实现备份采集；分别显示事件时间与采集时间，不以页面打开时间充当备份时间。
- [ ] 5. 运行 owner/CSRF、E2E、键盘和屏幕阅读器检查；失败保留输入和下一步操作，不显示“正常”伪装失败。
- [ ] 6. 输出 `docs/verification/P3.md`，完成 `git status`、`git diff` 和相关检查后提交 `feat(p3): 增加站长工作台与真实运行状态`。

## Acceptance

- 未登录、普通访客和站长分别得到正确的重定向、拒绝或工作台数据；所有写操作均通过 owner、CSRF/source、审计和重新认证要求。
- 内容、媒体和排期列表由 P3 提供后台列表页面，具体编辑、上传和排期事务由 P1 提供；双方不重复拥有同一路由。
- 概览能区分未配置、无记录、进行中、成功、失败、陈旧、读取失败和未知，并保留失败输入与下一步操作。
- 240px 侧栏、窄屏抽屉、键盘焦点、读屏、200% 文本和 reduced-motion 检查有独立证据；不探测外部服务、不显示虚构计数。
