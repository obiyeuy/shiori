# P4 备份部署与恢复 Implementation Plan

> **For agentic workers:** 使用 superpowers:subagent-driven-development 或 superpowers:executing-plans，按步骤逐项验证。

**Goal:** 建立不影响现有容器的独立部署、备份、异地回执和隔离恢复流程。

**Architecture:** Web/PostgreSQL 独立 Compose；镜像版本固定；迁移受控单独运行。服务器备份集以同一数据库快照绑定媒体清单；Mac 校验后回执；Giscus 导出独立计入状态；恢复演练使用新目录/新数据库。

**Spec:** 正式规格主体第 10/11 节、功能分册第 4 节及 O01–O09。

## Files

Create: ops/compose/*、ops/backup/server-backup.sh、mac-pull.sh、receipt-command.sh、src/lib/server/backup/*、src/routes/workspace/operations/*、scripts/restore-drill.ts、docs/operations/runbook.md  
Test: tests/integration/backup-receipts.test.ts、tests/e2e/recovery-drill.test.ts、tests/operations/o-scenarios.test.ts

## Interfaces

- createBackupSet(snapshot): Promise<BackupSet>
- recordMacReceipt(receipt): Promise<void>
- getOperationalStatus(now): Promise<OperationalStatus>
- runIsolatedRestore(backupSetId, target): Promise<RestoreReport>

## Steps

- [ ] 1. 写备份集测试：快照 ID、DB+媒体清单、校验和、未引用/历史媒体纳入、快照后新增归下一集。
- [ ] 2. 写回执测试：重复幂等、旧回执不倒退、校验失败不成功、回写失败待补发、Giscus 限流独立失败。
- [ ] 3. 实现只读状态目录和 Web 状态读取；区分事件/采集时间、最近成功/最近失败、陈旧/读取失败/未知。
- [ ] 4. 编写固定版本的 Compose、受控迁移和最小权限脚本；禁止带删除语义的同步、自动清理和 Web 持 SSH key/root/Docker。
- [ ] 5. 在只读核验服务器容量、域名/TLS/Cloudflare 路由和现有容器占用后，决定是否允许后续部署；本计划不执行部署。
- [ ] 6. 隔离恢复：新目录/独立 DB，关闭排期/备份/Giscus，旧会话失效，恢复 DB、媒体、配置，记录实际耗时和缺项。
- [ ] 7. 运行 O01–O09；任一不完整集保留最后可信恢复点并标失败/未知。
- [ ] 8. 输出 P4 报告和 commit feat: add backup and isolated restore runbook。
