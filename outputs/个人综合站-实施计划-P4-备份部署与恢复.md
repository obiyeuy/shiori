# P4 备份部署与恢复 Implementation Plan

> **For agentic workers:** 使用 superpowers:subagent-driven-development 或 superpowers:executing-plans，按步骤逐项验证。

**Goal:** 建立不影响现有容器的独立部署、备份、异地回执和隔离恢复流程。

**Architecture:** Web/PostgreSQL 独立 Compose；镜像版本固定；迁移受控单独运行。服务器备份集以同一数据库快照绑定媒体清单；Mac 校验后回执；Giscus 导出独立计入状态；恢复演练使用新目录/新数据库。

生产 Compose 与 P0 本地 Compose 使用不同项目名、网络、卷和端口；本计划不执行生产部署，也不修改现有容器。

**Spec:** 正式规格主体第 10/11 节、功能分册第 4 节及 O01–O09。

## Steps

- [ ] 1. 写备份集测试：快照 ID、DB+媒体清单、校验和、未引用/历史媒体纳入、快照后新增归下一集；定义加密、签名、密钥引用和机密字段脱敏规则。
- [ ] 2. 写回执测试：重复幂等、旧回执不倒退、校验失败不成功、回写失败待补发、Giscus 限流独立失败。
- [ ] 3. 实现 P0 `OperationalStatus` 契约的只读状态目录和 Web 状态读取；区分事件/采集时间、最近成功/最近失败、陈旧/读取失败/未知。
- [ ] 4. 编写固定版本的独立 Compose、受控迁移和最小权限脚本；使用独立项目名、网络、卷和端口，禁止带删除语义的同步、自动清理和 Web 持 SSH key/root/Docker。
- [ ] 5. 仅在用户提供只读访问方式后核验服务器容量、域名/TLS/Cloudflare 路由和现有容器占用，保存核验时间和证据；本计划不执行部署、不修改现有容器。
- [ ] 6. 隔离恢复：新目录/独立 DB，关闭排期/备份/Giscus，旧会话失效，恢复 DB、媒体、配置，记录实际耗时和缺项。
- [ ] 7. 运行 O01–O09；任一不完整集保留最后可信恢复点并标失败/未知。
- [ ] 8. 输出 `docs/verification/P4.md`，完成 `git status`、`git diff` 和相关检查后提交 `feat(p4): 增加备份与隔离恢复运行手册`。

## Acceptance

- 备份集包含快照 ID、数据库、媒体清单、未引用/历史媒体、校验和、签名/加密元数据，并能证明新增内容归入下一集。
- Mac 回执重复提交幂等、旧回执不能倒退、校验失败不标记成功；Giscus 失败独立呈现。
- Compose 使用固定镜像、独立项目名/网络/卷/端口；验证记录证明现有容器未被修改。
- 隔离恢复使用新目录和独立数据库，关闭排期/备份/Giscus，旧会话失效，记录耗时、缺项和最后可信恢复点；任何失败都标为失败或未知。
