# 个人综合站实施计划索引

> **For agentic workers:** 先读取本索引，再按依赖顺序逐个执行子计划；每个子计划都必须经过独立验证，未完成前不得进入依赖它的子计划。

**目标：** 将个人综合站拆为可独立评审、实施、测试和失败处置的计划单元；总索引只负责边界、依赖、跨计划契约和最终验收。

**设计依据：** 统一审阅入口及其批准的正式规格分册；不重新打开布局、主题、技术栈和素材后补决策。

## 子计划

1. **P0 工程基础与数据安全核心**  
   文件：outputs/个人综合站-实施计划-P0-工程基础与数据安全.md  
   交付：可复现工具链、SQL 迁移、内容模型、认证、会话和请求保护。  
   前置：无。后置：P1/P2/P3/P4/P5。

2. **P1 内容生产链：Markdown、媒体、版本、发布与排期**  
   文件：outputs/个人综合站-实施计划-P1-内容生产链.md  
   交付：共享渲染、媒体授权、编辑器、版本、发布、撤回、排期和审计。  
   前置：P0。

3. **P2 公开站、搜索与分发**  
   文件：outputs/个人综合站-实施计划-P2-公开站与搜索.md  
   交付：首页、六类公开内容、详情、标签、系列、搜索、RSS、站点地图、Giscus 按需加载。  
   前置：P0、P1。

4. **P3 站长工作台与运行可见性**  
   文件：outputs/个人综合站-实施计划-P3-工作台与运行状态.md  
   交付：概览、内容管理、系列/标签、媒体、排期、评论设置、服务目录、站点设置、账号安全和真实运行状态展示。  
   前置：P0、P1；消费 P0 定义的运行状态契约；P4 后续提供真实备份来源。

5. **P4 备份、部署与隔离恢复**  
   文件：outputs/个人综合站-实施计划-P4-备份部署与恢复.md  
   交付：独立 Compose、受控迁移、服务器备份、Mac 回执、Giscus 导出、运行手册和隔离恢复演练。  
   前置：P0、P1、P3；实现 P0 运行状态契约的备份来源，不反向依赖 P3 页面。

6. **P5 全量验收与上线门禁**  
   文件：outputs/个人综合站-实施计划-P5-全量验收与上线门禁.md  
   交付：A1–A9、S01–S16、O01–O09 追踪矩阵、浏览器/可访问性/性能/安全验证和上线输入清单。  
   前置：P0–P4 全部完成。

## 跨计划不可变契约

- 内容实体、可变稿、不可变版本、公开指针和至多一个未结束排期的关系由 P0 定义；后续不得各自重新建模。
- P1 的发布事务是 P2 公开查询、P3 工作台和 P4 备份的唯一事实来源。
- P2 只读取当前公开版本；P3 可读取后台状态；P4 读取经校验的运行记录；三者不得混用状态。
- 失败状态必须保留输入、旧成功时间或待确认结果；任何子计划都不能把失败伪装成空结果或正常。
- `OperationalStatus` 的枚举、时间字段和失败语义由 P0 定义；P3 负责展示，P4 负责备份/恢复来源适配，P5 负责验证。
- 不创建批量删除、目录删除、递归清理或历史媒体/版本/备份自动清理能力。
- 设计资料只读留在原目录；Banner/作品真实素材后补，不阻塞无图回退和计划执行。
- 每个子计划完成后必须产出自己的验证报告；总计划不得以“所有代码已写入”作为完成标准。
- 验证报告路径固定为 `docs/verification/P0.md` 至 `docs/verification/P5.md`；P5 汇总并链接 P0–P4 报告，同时产出自己的验收报告。
- 每个子计划只修改其 Files 中列出的路径；根级 `README.md` 与 `.env.example` 的章节 ownership 必须按 P0/P5 约定执行。

## 执行门槛

本索引及子计划获用户批准后，才选择 native 或 subagent-driven 执行方式。执行时一次只进入一个已满足前置条件的子计划；任一子计划失败，先按其失败处置停留在该计划，不跨计划掩盖失败。
