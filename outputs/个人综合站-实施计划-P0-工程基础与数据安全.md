# P0 工程基础与数据安全 Implementation Plan

> **For agentic workers:** 使用 superpowers:subagent-driven-development 或 superpowers:executing-plans，按步骤逐项验证。

**Goal:** 建立可复现 SvelteKit/Node/PostgreSQL 基础，并固定内容、权限、会话和审计契约。

**Architecture:** adapter-node Web 与 PostgreSQL 分容器；根目录 `compose.yaml` 仅用于独立本地开发项目，使用专用项目名、网络、卷和端口，不接管或修改现有容器；数据库迁移显式运行；内容公开投影从版本表生成。认证完全服务端，浏览器只持有安全会话 Cookie。

**Spec:** 统一审阅入口、正式规格主体第 1/5/7/8/10/11 节、功能与状态分册第 1/2/4 节。

- [ ] 1. 固定 pnpm、Node LTS、PostgreSQL 主版本、镜像 digest 和 lockfile；提交 `.nvmrc`、兼容矩阵、维护状态、许可证、安全限制及唯一复现命令到 toolchain.md。

- [ ] 2. 写工具链、字段、CAS 冲突、slug 命名空间、六类内容必填和公开投影失败测试。
- [ ] 3. 写 SQL 迁移：content_items、drafts、versions、URL aliases、tags、series、schedules、users、oauth_accounts、sessions、audit_events、site_settings、service_links；添加唯一约束、timestamptz、公开指针约束、每内容一个未结束排期约束，以及由 P2 使用的可选 `pg_trgm` 扩展/索引开关。
- [ ] 4. 实现 repository：草稿可不完整，发布前才校验；归档、公开、编辑、排期状态分离；公开查询只读取公开版本。
- [ ] 5. 实现 Argon2id、唯一站长初始化、GitHub 数字 ID 绑定、token 摘要、HttpOnly/Secure/SameSite=Lax、7 日最长/24 小时闲置策略、CSRF/source 检查和账户+来源限速。
- [ ] 6. 使用独立测试数据库运行 fresh migration、unit、integration、typecheck、build；未授权路由不得泄露公开以外的数据，并验证 Web 启动不隐式迁移。
- [ ] 7. 记录故障处置：迁移失败停在迁移；OAuth state/ID 不符即拒绝；冲突返回本地/服务器修订；不提供公网初始化或注册。
- [ ] 8. 输出 `docs/verification/P0.md`，完成 `git status`、`git diff` 和相关检查后提交 `chore(p0): 建立工程基础与数据安全核心`。

## Acceptance

- 新数据库可由单独迁移命令建立，Web 启动不隐式迁移。
- 草稿不完整可保存；公开版本、历史 URL、归档和排期边界通过集成测试。
- OAuth 访客不能抢占站长；会话可撤销；敏感操作要求重新认证。
- lockfile、Node/数据库版本和安装命令可在干净目录复现；迁移失败停在迁移且不启动半成品 Web。
- `OperationalStatus` 契约包含状态枚举、事件时间、采集时间、最近成功/失败和未知/陈旧语义。
