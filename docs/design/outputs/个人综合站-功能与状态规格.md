# 个人综合站：功能与状态规格

日期：2026-09-25。状态：正式设计规格的功能分册，新增细节按授权采用推荐基线，等待完整规格最终审阅。没有进入 writing-plans 或实现。

承接《个人综合站-正式设计规格-v0.1-待审阅.md》及用户已采纳的第 12 节。本分册补齐字段、状态、搜索行为和运行数据来源；不改变综合方案 v2、首版范围和既有确认。下文“必须”指目标验收要求，不代表已经实现或验证。

## 1. 六类内容的字段契约

### 1.1 共有字段与归属

草稿允许不完整并可自动保存；“必填”均指发布或建立排期前必填，不阻断保存草稿。所有公开字段来自当前公开版本，后台字段不能顺带序列化进公开页面。

| 字段 | 约束 | 归属与生效 |
|---|---|---|
| 内容 ID | 系统生成 UUID，不由标题生成 | 稳定实体，不可编辑 |
| 内容类型 | 文章、笔记、动态、作品、工具、资源六选一 | 创建时确定；首次发布后不可转换 |
| 标题/名称 | 除动态外必填，去除首尾空白后 1–120 个 Unicode 码点 | 草稿/版本，随发布生效 |
| slug | 必填，可自动生成并允许手改；同类型当前及历史路径不得被其他内容占用 | 草稿/版本保存目标值；发布时切换公开地址 |
| Markdown 正文 | 按类型校验；建议单篇上限 1 MiB UTF-8，超限不截断 | 草稿/版本 |
| 摘要 | 可选，最多 300 个 Unicode 码点；未填写时按下述规则生成 | 发布快照固定展示摘要 |
| 封面 | 可选，引用站内就绪媒体；无封面不留空位 | 草稿/版本 |
| 标签 | 可选、手工选择；建议 2–5 个，不强制数量 | 版本成员关系；显示名称遵循全局标签管理 |
| 评论开关 | 文章/笔记/作品默认开，动态/工具/资源默认关 | 草稿/版本；关闭不删除 GitHub 讨论 |
| 图片说明 | 有意义图片填写替代描述，装饰图显式标记为装饰 | 嵌入处保存；同一图片用于不同语境可不同 |
| 系列 | 仅文章/笔记，每篇至多一个 | 独立系列管理；编辑器只显示归属与入口 |
| 首页展示/精选顺序 | 仅符合类型的公开内容可选 | 站点设置；不属于正文自动保存 |
| 归档标记 | 默认否，可恢复 | 后台实体属性；不改变公开状态或排期 |
| 首次公开/当前版公开时间 | 系统记录实际成功时间，分开存储 | 首次公开时间不被重新发布覆盖 |
| 重要更新事件 | 每次发布默认不勾选，显式选择才生成事件 | 发布操作属性，不随历史恢复自动复用 |

字符计数规则用于校验，界面显示剩余容量；边界错误就地说明，服务端与界面采用同一规则。正文上限为推荐初值，后续资源验证可降低，但必须先提示并保留现有长稿的导出能力。

slug 推荐使用小写 ASCII 字母、数字与单连字符，1–100 字符，不以连字符开头或结尾。中文标题默认生成短随机标识，作者可改成英文短名，不增加拼音或翻译依赖。生成值也必须检查冲突；重复时提示更改，不静默改掉作者输入。URL 按内容类型分命名空间。

正文非空以可渲染内容判断：纯空白、空标记不算；有效站内图片、附件、代码、公式可以构成内容。动态仅有图片时要求图片描述或简短说明，以生成可读摘要；不强制动态另写标题。

摘要未填时，从正文提取前 160 个可读字符，忽略格式标记、代码/公式/Mermaid 源码，必要时使用媒体说明。工具和资源优先使用用途/说明字段。发布预览显示最终摘要，作者可修改；不能把内部路径、隐藏元数据或附件文件名自动作为摘要。若完全没有可提取文本，显示类型及公开日期作为中性列表文案，不把该文案写成作者标题。

### 1.2 各类型必填、可选与默认表现

| 类型 | 发布必填 | 类型专有可选字段 | 默认公开展示 |
|---|---|---|---|
| 文章 | 标题、正文、slug | 无额外必填项 | 正式长文，可显示目录；可进入最近更新/精选/系列/RSS |
| 笔记 | 标题、正文、slug | 无额外必填项 | 轻量知识记录；可进入最近更新/精选/系列/RSS |
| 动态 | 有效正文、slug | 标题、封面 | 时间线与独立详情；无标题时用正文摘要；进入最近更新/RSS |
| 作品 | 名称、一句话说明、正文、作品状态、slug | 封面、预览图组、演示 URL、源码 URL、关联公开文章/工具 | 作品详情与列表，可手选首页，进入 RSS，不进入最近更新 |
| 工具 | 名称、用途、可用状态、slug；可用时还需入口 | 正文、封面/站内图标、关联作品、不可用原因 | 用途优先；名称进说明页，“打开工具”进实际入口 |
| 资源 | 名称、说明、来源名称、来源 URL、slug | 正文、封面、作者、关联文章 | 可筛选资源目录与说明页；外链标记明确 |

一句话说明/用途/资源说明各 1–200 字符。作品预览图组是作品正文的辅助图片集合，不扩展成独立相册模块。关联内容按 UUID 保存，只渲染目前公开且类型合法的关联，失效关联隐藏，不显示草稿名称。

作品状态：进行中、已完成、暂停、已停止。状态描述项目生命周期，不表示演示链接已通过健康检测。无演示/源码链接仍可发布展示型作品，不虚构按钮；不同状态都可展示详情。

公开工具状态：可用、维护中、暂不可用、已停用。默认新草稿为暂不可用；后三种发布时须有原因，禁用“打开工具”，保留说明和相关作品链接；不把停用等同撤回。所有状态均由站长设置，不自动探测。入口只接受本站相对页面路径或无凭据的 HTTPS URL；本站路径不得指向工作台、登录、预览、私有媒体或写操作接口。

首版交付工具目录与已有公开工具入口，不包含尚未指定用途的新工具程序。站长私有服务单独管理，不能因填写到公开工具字段而绕过公开确认。私有服务保留其实际 HTTP/HTTPS 访问方式并标识是否加密，接入前核验；不擅自修改现有服务。

资源来源 URL 使用 HTTPS 或 HTTP，HTTP 明示非加密链接；所有外链禁止凭据和脚本协议。来源不可达不阻止内容发布，首版无自动链接巡检。

## 2. 状态与操作的共同语言

### 2.1 内容状态按维度组合

| 维度 | 状态 | 界面含义 |
|---|---|---|
| 公开 | 从未发布 / 已公开 / 已撤回 | 是否有公开版本指针及历史发布记录 |
| 编辑 | 与公开版一致 / 有未发布修改 / 未发布草稿 | 比较可发布字段，不以保存时间判断；从未发布或已撤回时显示未发布草稿 |
| 排期 | 无 / 待执行 / 重试等待 / 失败待处理 | 同一内容最多一个未结束排期；失败排期仍占据该位置 |
| 后台收纳 | 常规 / 已归档 | 仅控制默认内容列表，不遮住异常和排期 |

展示示例：“已公开 · 有未发布修改 · 9月28日 20:00 排期”；“已归档 · 已公开 · 排期失败”。公开访客不看到这些后台状态。列表筛选标签采用同组多选 OR、不同组 AND；默认不显示归档，显式选择后可查到。

### 2.2 排期状态与失败恢复

排期从待执行进入执行处理，成功为已发布，取消为已取消。执行处理可用短期任务占用表达，但必须可回收，进程退出不能使任务永久卡死。重启先核对是否已完成发布，再决定是否补发。

瞬时故障推荐在首次失败后间隔 1、5、15 分钟最多自动重试 3 次；每次显示原因、次数和下次时间。该阶段不再承诺一分钟内发布。校验冲突、引用缺失或 slug 冲突直接转为失败待处理，不自动无限重试。重试前重新检查排期仍有效及目标版本；取消成功后不得继续重试。

失败后的操作：重试同一版本、更新排期版本、修改时间、取消排期。更新版本必须明确选择新快照，不能悄悄使用当前编辑稿；修改时间不修改快照。手动重试重新开启有上限的尝试周期并记录操作者。用户排期时间必须晚于服务端当前时间；停机错过后由系统补发属于另一种情况。

### 2.3 编辑器与媒体状态

保存区固定位置显示未保存、保存中、已保存时间、离线、失败、会话过期或冲突；优先展示阻碍保存的状态。错误恢复后显示真实保存时间，不只隐藏错误。正在提交时合并后续自动保存，不并发发送相互覆盖的全文；用户可继续输入。发布只使用服务端已确认的修订，面板不把“保存中”当成已保存。

媒体状态为待上传、上传中、处理中、就绪、失败。上传进度与处理状态分开，不伪造处理百分比；取消当前传输不意味着删除已接收文件。失败项支持重试或从当前稿移除引用，移除引用不删除文件。暂存残留、无引用媒体和历史引用均保留，容量管理不包含自动清理。

### 2.4 发布前检查与结果

| 情况 | 行为 |
|---|---|
| 必填字段缺失、slug 冲突、站内引用缺失、上传未完成 | 阻止发布/创建排期，列出问题并聚焦对应字段 |
| 无标签、无封面、未填写手工摘要 | 允许；面板显示实际回退效果 |
| 存在已公开附件 | 提示已公开事实，不能暗示本次撤回可让其保密 |
| 外部链接尚未验证、评论加载失败 | 不阻止正文发布，不虚构验证成功 |
| 目标修订或排期状态已变化 | 停止提交，保留选择并要求核对最新状态 |
| 提交响应丢失 | 查询操作结果；结果未知时保留“结果待确认”，不立即当成失败重发 |

成功反馈包括公开页入口、实际发布时间和排期处理结果。失败反馈保留正文、面板选择与旧公开版本；用户可以重试、返回编辑或导出。接口重试必须具有幂等语义。

## 3. 搜索行为与验收样例

### 3.1 用户可预期的搜索契约

关键词去首尾空白，统一连续空白；大小写不敏感，匹配副本做 Unicode NFKC 规范化，原文展示不被改写。按空白分成至多 8 个查询片段，片段之间 AND，可跨标题、标签、摘要和正文匹配；连续中文片段按连续文本匹配，不要求中文分词。关键词最多 100 个 Unicode 码点，超限提示缩短，不静默截断。

首版不提供高级布尔语法、引号语法或正则搜索。标点按字面处理，C++、C#、Node.js 与 pg_trgm 中的符号不可一律剥离。SQL 通配字符 % 和 _ 也是普通查询字符，不允许把用户文本当作查询表达式。无查询词时显示输入提示，类型/标签单独浏览走栏目页。

每个查询片段至少命中一个搜索字段。相关性首先比较标题命中片段数，再比较标签、摘要、正文命中片段数；相同条件下完整查询命中标题优先，再按首次公开时间倒序、稳定 ID 打破平局。英文词干/模糊匹配只可作为后续增强，不能让字面命中从结果中消失。索引方案不得改变这些可观察行为。

类型筛选在所选类型间 OR，标签筛选在所选标签间 OR；关键词、类型组、标签组之间 AND。URL 保存关键词、类型、标签与页码；参数规范化并验证，非法标签/类型不静默退回全站搜索。更改条件回到第 1 页，分页每页 20 项；超出最后一页显示明确提示与返回入口，不把查询失败显示为空结果。

片段显示实际命中上下文，最多约 160 字符；代码命中可显示转义后的代码片段，绝不执行搜索结果里的 HTML。没有正文命中时显示公开摘要，并可标记“匹配标签”。结果总数、筛选计数与片段全部来自当前公开版本。首版标签统计可以不显示，不能混入未公开总数。

搜索样例是后续实现必须验证的期望，当前未运行数据库测试。pg_trgm 若无法有效加速某些字符或短词，允许使用有资源上限的字面匹配；超时显示可重试错误和缩小范围建议，不给出假装完整的部分结果。代表性服务器验证建议使用 1,000 与 10,000 篇、每篇约 5 KiB 的中英文混合样本，查询超时初值 2 秒，目标数据库查询 p95 ≤500ms；这是验收目标，不是现有测量结果。

## 4. 备份与运行信息来源

### 4.1 一个备份集的身份与成功条件

每次服务器备份生成唯一备份集 ID，记录数据库快照点、应用/结构版本、媒体清单摘要、文件数量和字节数、各文件校验摘要、开始/完成时间。成功标记在数据库转储完成、文件复制与清单校验通过之后写入，不能先写成功再复制。

数据库转储与媒体引用清单必须基于同一数据库快照（推荐导出一致快照并供两者共享）；文件不可变及禁止自动清理确保后续复制仍能取到所需文件。包含草稿、历史、排期和站点设置引用的原图/派生文件及必要媒体元数据；未引用但仍保存的媒体也进入完整备份清单。快照后新上传文件属于下一备份集，不算本次漏备。

服务器备份成功仅表示本机可校验副本；Mac 接收到完整清单、转储和媒体并逐项验证后才生成异地成功回执。Giscus 单独记录导出 ID、分页完整性和完成时间，不用数据库成功状态覆盖其失败。必要配置随版本备份，密钥独立加密，密钥副本不可显示在工作台或日志。

### 4.2 推荐的完成记录通道

推荐沿用 Mac 拉取所需的 SSH 通道：服务器专用备份账户提供备份目录只读访问，并通过受限接收命令接收 Mac 回执。不新增公开 HTTP 回调接口，也不让浏览器传入任意服务器路径或执行命令。

专用账户不是日常管理员，不拥有 Docker socket 或通用 root 权限；接收命令只接受固定字段、已有备份集 ID 和匹配的清单摘要，保存到专用回执目录。Web 应用只读挂载状态目录并读取经过校验的记录，不获得 SSH 私钥或写入备份文件的权限。该通道是设计推荐，尚未配置或核验现有 SSH 环境。

回执包含备份集 ID、清单摘要、Mac 验证完成时间、接收时间、文件数与字节数、验证结果、备份设备标识。展示可读备份设备名称，不在公开页面暴露本地路径。传输中断或回写失败时 Mac 保留待发送回执，联网后补发；同一集的重复成功回执幂等处理。

收到旧集回执时不覆盖较新恢复点；只有更晚数据库快照点的完整有效回执才能前移“最新异地恢复点”。不以 Mac 自报完成时间决定恢复点新旧。回执代表受信任 Mac 校验程序报告，不声称服务器能远程证明 Mac 磁盘永久可读。

### 4.3 指标与显示规则

| 项目 | 原始来源 | 刷新/新鲜度推荐 | 异常和操作 |
|---|---|---|---|
| 排期扫描 | 应用每轮扫描写入开始、成功结束或失败记录 | 30 秒扫描；最近成功超过 2 分钟则陈旧 | 显示扫描陈旧/失败和最近成功时间；到期未发单独提醒 |
| 服务器备份 | 本机备份程序的完成记录及校验清单 | 每日；最新完整快照年龄超过 26 小时提醒 | 查看失败阶段；保留最后成功，不用失败覆盖历史 |
| Mac 异地副本 | 上述回执 | 最新成功备份集的快照年龄超过 26 小时提醒 | “异地恢复点已过期/待确认”；不能直接断言 Mac 离线 |
| Giscus 导出 | 独立导出程序记录 | 每日尝试；超过 26 小时提醒 | 说明评论备份失败不等于正文备份失败 |
| 存储容量 | 本站数据库/媒体/备份路径所在文件系统采集 | 每分钟采集；超过 5 分钟则陈旧 | 显示剩余字节及百分比；共用分区去重，不重复相加 |
| 当前编辑保存 | 当前浏览器及服务端保存响应 | 随当前编辑更新 | 只代表当前会话；冲突/失败可直达当前编辑器 |

工作台打开时读取最新记录，页面可每 60 秒轻量刷新；后台采集与页面刷新分开。显示“数据采集于”和“事件发生于”，不把打开页面的时间伪装成备份时间。时区统一 Asia/Shanghai；数据库事件保留明确时间点。

阈值用于提醒，不是可用性保证。容量未知时停止接受新增媒体并说明无法校验容量，现有阅读保持可用；编辑保存仍以真实数据库写入结果为准，不承诺磁盘耗尽时可继续保存。日志限额通过限制写入量/速率设计，不采用自动删除历史文件的轮转清理。

每项记录状态区分：未配置、尚无记录、进行中、最近一次成功、最近一次失败、记录陈旧、读取失败。最近一次失败与最近成功时间同时展示；成功记录变旧后不能仍只显示绿色“正常”。长时间进行中显示“运行超时，结果待确认”，不能凭网页计时宣布进程已终止。自动任务最大运行时长为部署参数，首版建议 2 小时提醒，后续以样本测量调整。

最近异地恢复点以对应数据库快照时间计算，而非刚刚补拉完成的时间。例如今天补拉三天前备份，界面仍显示三天前恢复点。没有回执显示未知，不能当成严格零备份，也不能声称已恢复保护。

### 4.4 恢复验证与运行验收

| 编号 | 场景 | 期望 |
|---|---|---|
| O01 | 服务器成功、Mac 无回执 | 本机成功，异地未知/过期；无“全部备份正常” |
| O02 | Mac 复制完但校验失败 | 不生成成功回执；显示失败阶段，保留之前恢复点 |
| O03 | Mac 校验成功但回执发送失败 | Mac 保存待发送记录；服务器保持未知或旧状态，补发后更新 |
| O04 | 同一回执重发、旧回执晚到 | 幂等；恢复点不会倒退 |
| O05 | 媒体复制时新增内容 | 本集与既定快照清单一致，新内容由下一集覆盖 |
| O06 | 部分媒体缺失/校验不符 | 本集不标记完整成功，不静默跳过缺失文件 |
| O07 | Giscus 导出中途限流 | 单独失败并可继续重试，不影响正文已成功副本 |
| O08 | 采集进程停止 | 工作台显示陈旧，不靠页面刷新制造新采集时间 |
| O09 | 隔离恢复演练 | 从指定集恢复数据库、原图、引用与配置；记录实际耗时及缺项 |

恢复演练使用新目录与独立数据库，不覆盖现有服务，不清理旧演练目录。先以私网/隔离方式校验，关闭排期执行、备份上报和评论加载，防止演练实例自动补发或污染线上记录；确认后才在受控接管步骤恢复任务。备份中的旧会话全部失效，重新登录；排期记录保留，真正恢复上线时按已确认补发规则处理仍有效的任务。

## 5. 本分册自审与剩余设计

本分册完成了六类内容字段、作品/工具状态词、组合状态、错误恢复、16 组搜索行为样例，以及备份回执通道和 9 组运行验收场景。它们是设计要求，未进行产品代码、数据库、服务器或浏览器实现测试。

ui-ux-pro-max 的反馈规则支持提交中/成功/失败的明确反馈；搜索结果中的批量操作建议不适用于本项目的删除限制，未采纳。记录陈旧的具体阈值来自本项目每日备份和 30 秒排期节奏的设计判断，不声称技能数据库提供了这些数值。

下一项是视觉分册：浅深语义色与实际对比度、组件状态、完整首页及关键页面设计稿。此后合并正式规格、去除历史歧义，交用户最终批准；本分册完成不授权 writing-plans 或实现。
