## 2. 冲突时的优先级

用户明确要求及已确认决策优先；架构主体第 12 节为已采纳的修正。功能分册细化可观察行为，视觉分册细化组件，v2 控件细稿覆盖概览画板的简写。图片中的样例文案、示意图和简化元信息不能改变权限、发布和访问规则。

以下高风险歧义统一为确定规则：

- 自动保存只更新编辑稿；发布才改变公开版本；重要更新属于发布事件。
- 手动发布默认取消已有排期，可明确选择保留；恢复历史只生成新稿。
- 内容归档仅收纳后台列表，不改变公开状态；撤回停止公开并取消有效排期。
- slug 随发布生效，历史地址保留归属和跳转；内容 ID 不变。
- 文件准备与公开授权分开，原图默认受保护；撤回正文不承诺已公开附件重新保密。
- 系列关系独立保存，不随正文自动保存或历史恢复一起改变；上下移动是独立操作。
- 服务卡片状态是人工记录，Giscus 不等于本站审核队列；备份状态必须有真实来源和时间。
- 首页介绍、更新、精选、作品、工具按确认顺序分区；无公开工具时隐藏公开工具导航。

## 4. 尚需完成的事项

### 4.1 已获准后补的素材与后续视觉验证

1. 正式 Banner 与作品图尚未提供或选定。当前仅验证无图回退和布局，不宣称已实现日系场景氛围。需有授权素材后检查桌面/手机焦点及文字可读性。
2. 静态图片使用系统替代字体，目标字体的字形、字重和实际换行仍需复核。此项不能以旧颜色计算结果代替。
3. 用户已审阅通过除暂缓素材外的设计，包括整体密度、阅读结构和补充页面；不再重复请求设计批准。目标字体排版复核转入后续计划中的验证项，不更换既定字体。

素材延期已由用户明确授权，不阻塞实施计划。未有正式素材时使用已确认的无图/无封面状态；素材到位后再验收授权、裁切和文字可读性。当前不需要索要素材或擅自采购、生成、下载正式资产。

### 4.2 已设计、须在后续获准的工程阶段验证

依赖维护状态与兼容版本、中文搜索索引性能、图片资源阈值、实际服务器余量、备份恢复耗时，以及真实键盘/读屏/输入法/响应式行为。后续实施计划必须安排验证及失败处置，本阶段不为验证这些事项提前写产品代码或部署。

### 4.3 上线输入

真实站名/定位、域名、GitHub OAuth/Giscus 配置、公开工具和内容、服务实际地址与认证、备份目录及运行时段。它们不需要重新讨论已确认原则，但没有这些输入不能宣称可上线。

## 5. 批准的含义

用户已完成正式规格审阅，素材后补。本轮按用户要求整理交接，不调用 writing-plans；新会话应直接读取规格并使用 writing-plans 形成可审阅的实施计划。实施计划仍需用户审阅后再实现，不可将设计批准扩展成创建项目、安装依赖、写产品代码或部署的授权。

用户只回复“继续”时，继续设计与审阅收敛，不能解释为正式规格批准。不得因画板数量增加、已读完文档或工具检查通过而跨越此边界。
