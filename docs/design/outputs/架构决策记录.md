- 编辑器：源码/预览共享规则，推荐 CodeMirror 6 + unified/remark/rehype + KaTeX/Shiki/Mermaid，版本兼容性待核验；自动保存防抖约 2 秒、持续输入约 15 秒保存，乐观锁防多标签页覆盖，10 分钟变化检查点。

### 首页分区版式确认（续）

- Banner 素材规范已确认：优先有环境的日系场景插画，人物可有可无；桌面主体偏右，左侧保留文字空间。欢迎语为独立文字，不烘焙进图片；只在文字区域按需加渐变，不整体压暗、模糊或褪色。移动端可独立设置焦点，并可上传同场景手机版本；仍为一个稳定 banner，不轮播。深色模式默认保留插画原色，通过周围界面和局部遮罩衔接。后台提供桌面与手机预览后确认替换。

- 精选采用一主两次：桌面左侧主推荐、右侧两篇纵排；手机按主次单列。站长手动排序，第一篇为主推荐；封面可选，数量不足时自然收缩，不补空卡片。
- 作品采用大图分行：桌面每件作品的预览与介绍左右分列，不强制交替方向；手机图片在上、说明与入口在下。优先真实成果截图或创作成品，最多 3 件。
- 工具采用紧凑入口列表：图标、名称、用途、状态、打开按钮；开发故事进入相关作品详情。移动端单列，保证触控尺寸。
- 精选、作品、工具维持独立区域与既定顺序，通过留白形成区隔，不为每区再套边框，不旋转或随机错位。
- 补齐已确认的状态规则：banner 加载或失败保留背景与欢迎语；最近更新为空时文字提示，其余空分区隐藏；已知不可用工具保留说明、原因并禁用打开动作；外部故障不阻断其他内容。hover 使用背景、边界或箭头反馈，标签显示文字且可筛选，保留键盘焦点、浅深主题和 reduced-motion。

## 已确定

### 产品定位

- 这是一个以内容为主的个人综合站，不是传统个人简历页。
- 个人介绍保持简短；通过文章、笔记、作品和工具体现个人方向。
- 正式内容和随性记录都保留，但通过栏目区分。
- 计划包含：个人首页、文章、笔记、动态、作品、工具、资源/收藏，以及后续的私人空间。
- 私人空间计划包含日记、任务、文件等，权限另行设计。

### 首版公开栏目

- 首页
- 文章
- 笔记
- 动态
- 作品
- 工具
- 资源
- 关于

### 首版暂缓或后置

- 私人日记
- 私人任务
- 私人文件工作台
- 公众注册
- 复杂评论系统
- 图数据库、向量数据库、独立搜索服务

### 技术路线

- 自建，不采用 Halo。
- 前后端技术栈：SvelteKit。
- 数据库：PostgreSQL，作为独立 Docker 容器运行。
- PostgreSQL 通过 Docker 内部网络供 SvelteKit 使用，不开放公网端口。
- Web 应用和数据库在同一个 Docker Compose 项目中，但使用不同容器。
- 浏览器不直接连接数据库，由 SvelteKit 服务端访问数据库。
- 公开页面、后台、工具和服务端 API 先保持在一个 SvelteKit 应用中。

### 部署与服务器

- 使用现有服务器：Ubuntu 24.04.4 LTS，x86_64，4 个逻辑 CPU，约 3.6 GiB 内存。2026-09-25 本轮只读复查：根盘约 40 GB，已用约 21 GB，可用约 17 GB（df -h 显示）。旧的剩余 9.8 GB 仅为历史快照，不再作为当前容量依据。部署时重新检查。
- 现有服务必须保持不动。
- 使用独立 Docker Compose 项目、独立网络、独立持久目录。
- 使用子域名接入；具体子域名前缀尚未确定。
- 现有 Cloudflare Tunnel 可作为接入方式，但正式部署前仍需验证路由，不假设其一定是最终入口。
- 数据库不开放公网端口。

### 数据与媒体

- PostgreSQL 是内容的正式数据来源，文章、笔记、动态、作品、资源等进入数据库。
- 文章和笔记正文使用 Markdown 文本保存。
- 公开页面由 SvelteKit 将 Markdown 渲染为 HTML；HTML 是输出结果，不是正文原件。
- 图片、视频、PDF 和其他附件不直接存数据库，保存到宿主机持久目录并挂载到 Web 容器。
- 数据库记录媒体文件的相对文件键、类型、大小、尺寸、所有者和可见性等元数据。
- 文章中的图片使用站内相对 URL，例如 `/media/2026/09/example.webp`；不写入宿主机绝对路径。
- 公开媒体与私人附件分目录；私人附件不能作为公开静态目录直接暴露。
- 数据库、媒体、必要配置和密钥需要一起备份；要提供通用内容导出，以便未来迁移到其他系统。

### 发布与编辑

- 内容编辑、草稿、预览和发布通过管理后台完成。
- 自动保存不能直接覆盖公开版本；编辑版本与公开版本分离。
- 点击发布才更新公开内容。
- 文章、笔记、作品支持 Markdown 编辑和图片插入。
- 动态使用更轻量的发布流程。
- Markdown 支持导入和导出，但不再把本地 `.md` 文件作为网站正式内容源。

## 已排除或修正的方向

- 不使用 Halo。
- 不把网站做成传统“前端项目 + 独立后端项目”的多仓库架构；首版保持一个 SvelteKit 全栈应用。
- 不单独部署传统图床服务；媒体上传和访问属于网站的媒体模块。
- 不把图数据库当成图片存储；图数据库当前没有必要。
- 不把图片二进制默认塞进数据库。
- 已选择自建，不采用 Payload 等 CMS 作为基础。此前因 MySQL 排除 Payload 的理由已过时：目前已选 PostgreSQL，技术上可以兼容，但不因此重新启动 CMS 选型。
- 不因为服务器已有 Cloudflare Tunnel 就跳过实际路由验证。

## 设计原则

1. 公开内容优先，个人介绍保持克制。
2. 先建立清晰的数据边界，再增加功能。
3. 内容发布与代码部署分开。
4. 应用容器可重建，数据库和媒体不可依赖容器临时层。
5. 迁移不依赖宿主机绝对路径或某个云厂商。
6. 权限必须在服务端和文件访问层落实，不能只隐藏前端入口。
7. 先测量服务器资源，再确定缓存、图片处理和服务数量。
8. 不提前引入图数据库、向量数据库、Redis、Elasticsearch 等复杂基础设施。

## 推荐基线收敛（覆盖前述尚未决定，待正式规格审阅）
